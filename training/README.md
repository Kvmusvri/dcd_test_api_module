# Цветовая LoRA (Qwen-Image-Edit-2511) — запуск и контроль

**Два отдельных шага, оба с видимым прогрессом в терминале.**

## Шаг 1. Закачка весов (один раз, ~40,9 ГБ, продолжается с места остановки)

```
make lora-download
```

Качает исходную модель Qwen-Image-Edit-2511 (transformers-формат, нужен
для обучения) в кэш `Z:/hf_cache`. Прогресс-бары со скоростью видны;
готовые файлы пропускаются, битые докачиваются. Это НЕ файлы из
`diffusion_models` (те — fp8-экспорт для ComfyUI, обучаться на них нельзя).

## Шаг 2. Обучение

```
make lora
```

Проверит датасет (250 пар, `storage/lora_dataset`), докачает недостающее
(мгновенно, если шаг 1 сделан) и запустит обучение — 2400 шагов с батчем 1,
трекинг шагов и лосса прямо в консоли. В конце готовый LoRA копируется в
`Z:\ComfyUI\models\loras\car_recolor_qwen_edit_2511_v1.safetensors`.

### Ограничение шагов (смотреть динамику)

```
make lora 500
```

Число после цели — лимит шагов (можно `make lora 250`, `--steps 500` и т.п.).
Лимит пишется только в копию конфига на Z:, репозиторий не меняется.
Обучение дойдёт до лимита и установит последний чекпойнт как LoRA;
**следующий `make lora` без числа продолжит с последнего чекпойнта**
(ai-toolkit восстанавливает веса, шаг и оптимизатор) до полных 2400.
Если чекпойнт с шагом ≥ лимита уже есть — обучение пропускается,
ставится существующий чекпойнт.

Лестница проверки (замер 35–38 с/шаг; без ComfyUI и десктопной нагрузки
может быть быстрее): 250 ≈ 2,5 ч — красит ли вообще; 500 ≈ 5 ч — первая
осмысленная оценка цвета; 750 ≈ 7,5 ч — рабочий кандидат на ночь;
дальше 1500/2400 — добивка, если цвет ещё плавает. Останавливаться
выгодно сразу после строки «Saved checkpoint» — недописанный хвост
до чекпойнта при остановке теряется.

## Остановка

`Ctrl+C` в том же окне **или** (если окно закрыто) `make lora-stop`.
Датасет и скачанные веса сохраняются; обучение после остановки
начинается с шага 0 (веса качать заново не нужно).

## Использование

Когда LoRA появилась в loras — в селекте провайдера на вкладке «Оклейка»
выбрать **ComfyUI · Qwen-Image-Edit (локально)** и генерировать.
Пост-грейд цвета работает одинаково для обоих провайдеров (лог: `grade detail`).

ComfyUI поднимается/гасится вместе со стендом (`make rebuild/up/down`).

## Замечания

- **Капшены датасета — теги плёнок** (код SKxxxx, решение 2026-09-25):
  цвет зашивается за кодом. При генерации свотч плёнки должен быть файлом
  из каталога (или его пересжатой копией) — тогда бэкенд сам подставит
  тег в промпт. Чужая плёнка → штатная инструкция, цвет добивает пост-грейд.
- Батч обучения — строго 1. Каждый контрол (машина, плёнка) ресайзится на
  площадь 1 Мпикс по своим пропорциям — и на тренировке, и на инференсе
  ComfyUI, поэтому длина токенов у пар разная и батч из двух пар физически
  не склеивается. Шаг на батче 1 вдвое дешевле, поэтому шагов 2400 — по
  объёму данных как планировалось. Чекпойнты каждые 250: если на раннем
  чекпойнте цвет уже точный — можно останавливаться (Ctrl+C ставит
  последний чекпойнт как LoRA), доучивать не обязательно.
- Во время обучения карта занята (~20 ГБ) — параллельная локальная
  генерация может падать по VRAM. После обучения — свободно.
- Свежий ComfyUI обязателен: нужны ноды TextEncodeQwenImageEditPlus,
  FluxKontextMultiReferenceLatentMethod, CFGNorm.
- Датасет пересоздать: удалить `storage/lora_dataset`, перезапустить
  стенд (автогенерация соберёт заново), затем `make lora`.
- Выход ComfyUI ~1 МП, пропорции клиентские; итог дорастягивается
  `match_size`-ом как раньше.
- Лицензии: Qwen — Apache-2.0; Lightning-LoRA lightx2v (по решению Льва
  лицензии не блокируют).
