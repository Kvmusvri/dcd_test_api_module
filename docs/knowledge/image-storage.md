# Хранилище изображений и дедупликация

## Реализовано (2026-09-07)
- Структура: `storage/images/YYYY-MM-DD/incoming|outgoing/<sha256>.<ext>`
- Файл именуется контент-хешем SHA-256.
- **Дедупликация**: перед записью ищется существующий файл с тем же хешем в БД; если найден — создаётся **жёсткая ссылка** (os.link) в каталог сегодняшней даты/направления, место не расходуется, но папка дня визуально полная. При ошибке линка (файловая система) — копия.
- Метаданные: **SQLite** `storage/metadata.db`, таблица `images` (hash, rel_path, date, direction, ext, size, mime, model, prompt, request_id, created_at). Индексы по hash/date/request_id.
- Отдача: `GET /api/images/{id}/file` с `ETag = hash` и `Cache-Control: immutable` → браузер кэширует, повторные показы мгновенные.
- Связь вход↔выход: общий `request_id` на партию (12 hex-символов).
